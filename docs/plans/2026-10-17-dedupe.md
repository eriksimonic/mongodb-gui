# Plan: remove the duplication PMD CPD reports

## Goal and done check

PMD CPD at 60 tokens reports 53 source clusters and 211 test clusters (`docs/plans/2026-10-17-dedupe.cpd-baseline.md`). This plan removes the source clusters it can fix without changing app behavior, and the test clusters where a shared helper makes the tests easier to read. Pure shared logic moves to `packages/core`, and the adapter, the app and the UI mocks import it.

Done check, all must pass on branch `refactor/dedupe`:

1. `pnpm typecheck && pnpm lint && pnpm test` pass, or fail only with the failures D0 recorded.
2. `pnpm test:integration` passes, run once under the Docker lock. It covers the adapter refactors in S4 to S8 and S16 and the files T4 and T5 edited.
3. `E2E_SEGMENT=standalone pnpm test:wiring` on the specs T9 edited passes, and `E2E_SEGMENT=replset pnpm test:wiring` on the specs T10 edited passes.
4. F1 reports no new cluster and no grown cluster between the T0 commit and the branch head, and every baseline source cluster is gone except the ones under "Left alone".

## Constraints and do-not-change list

- No app behavior change. The one exception is the management mock's collection options (S7), which switch to the real logic. Mock error and warning texts stay the same everywhere.
- RPC contract schemas keep their inferred types. Rebuilding a zod object with `.extend` is allowed, and changing a field is not.
- The SQL text in `packages/storage/src/store/migrations.ts` does not change.
- No new dependencies. No edits to `docs/screenshots`, `e2e/coverage-map.ts` or `.idea/`.
- No task edits `packages/core/src/index.ts`. Every new core helper goes into a module that `index.ts` already re-exports. An implementer that finds it needs a new export line stops and reports to the coordinator.
- Exported names change only where a task brief names them.
- Leave the running `mongo-gui-perf-rs*` containers alone.
- Nothing is pushed or merged.

## Pattern to copy

The uncommitted work in the tree, which T0 commits:

- `packages/core/src/replication/patch-rules.ts` holds `memberPatchRefusal`. `packages/mongo-adapter/src/replication/reconfig.ts` and `packages/ui/src/replication/mock.ts` both call it.
- `packages/core/src/sharding/summary.ts` holds `drainDryRun`. `packages/mongo-adapter/src/sharding/operations.ts` and `packages/ui/src/sharding/mock.ts` both call it.

The rule: the logic lives once in core, has no driver or DOM types, and the real code and the mock import it. A mock that imports the real logic is the preferred fix for a mock-versus-real cluster.

Test helper placement follows `packages/mongo-adapter/src/test/`: helper modules live in `src/test/`, the package `tsconfig.json` excludes `src/test/**`, and `tsconfig.test.json` (which includes all of `src`) still typechecks them. Helpers may then import `vitest`.

## Decisions made by the planner

- Implementers work in their own git worktree, so a half-done edit in one task does not break the typecheck of another. The coordinator creates it with `git worktree add ../mongo-gui-wt/<id> -b dedupe/<id> refactor/dedupe`, then runs `pnpm install --prefer-offline` in it. The validator runs in the same worktree. After a pass the coordinator commits there, cherry-picks the commit onto `refactor/dedupe` and removes the worktree.
- The plan, the baseline and the status file stay untracked in the main checkout until the end, so worktrees do not have them. Every brief cites them by absolute path: `/home/erik/Documents/mongo-gui/docs/plans/2026-10-17-dedupe.md`, `.../2026-10-17-dedupe.cpd-baseline.md` and `.../2026-10-17-dedupe.status.md` in the same folder.
- `@mongo-gui/core` resolves to `src/index.ts` (package.json `main` and `exports`), so consumers see a new core export without a build step.
- Where two copies differ, the brief names the copy that wins. Tests decide: the existing unit tests must pass unchanged, except where a brief says a mock test changes.
- `migrations.ts` is left alone. Applied migration SQL is history, and a shared table builder that someone edits later would change fresh installs but not existing ones. See open decisions.

Each call site uses the shared function with `?? text.length`, because the formatter's copies return `text.length` where the tokenizer's return undefined. - S2. Create `ui/src/editor/code-scan.ts`:

  ```ts
  export interface CodeScanEnd {
    /** The index where visit returned true, or undefined when the scan reached end. */
    readonly stoppedAt: number | undefined;
    /** True when end falls inside a string or a comment. */
    readonly insideLiteral: boolean;
  }
  export function scanCode(
    code: string,
    start: number,
    end: number,
    visit: (char: string, index: number) => boolean | void,
    options?: { readonly comments?: boolean },
  ): CodeScanEnd;
  ```

  `scanCode` calls `visit` for each character outside strings and comments. It does not visit quote characters, comment markers, characters inside strings or comments, or the newline that ends a `//` comment. A backslash inside a string skips the next character. `comments` defaults to true. With false, `//` and `/*` are ordinary characters. Switch three loops to it: `splitStatements` in `statements.ts`, `openFrames` in `signature.ts` (it returns undefined when `insideLiteral`), and `skipCall` in `result-model.ts` with `comments: false`, returning `stoppedAt + 1` when the character there is `)`. `splitStatements` drops the `index = segmentStart - 1` jump after a blank line. Skipping it is equivalent, because the skipped characters are spaces and newlines at depth 0. In `statements.ts`, also add `pickStatement(statements, offset): Statement | undefined` (the body of `statementAt` after the split) and `runTargetWith(code, cursor, selection, find: (code: string, offset: number) => Statement | undefined): RunTarget` (the body of `runTargetFor`). `statementAt`, `runTargetFor`, `sqlStatementAt` and `sqlRunTargetFor` become one-line calls. The existing tests must pass without edits.

## Finishing validation

F1 runs after every other task and done checks 1 to 3 have passed. It follows the `cpd-duplication` skill:

1. Check out two read-only trees: the T0 commit (hash in the status file) with `git worktree add /tmp/cpd-before <hash>`, and the head of `refactor/dedupe`. For each, build a `files.txt` from `git ls-files '*.ts' '*.tsx' | grep -v '\.d\.ts$'`, the same file set rule as the baseline.
2. Holding the Docker lock, run one `eclipse-temurin:21-jre` container with `--rm` that mounts both trees read-only. Resolve the PMD tag once inside it, write the tag into the status file, and run `pmd cpd --language typescript --minimum-tokens 60 --format xml --no-fail-on-violation` on each file list. Both reports come from the same PMD version.
3. Compare the two reports without line numbers. A cluster is new when its set of files and token count does not appear in the before report. It has grown when the same file set appears with more tokens. Clusters that involve a file this plan created count as new and are reported. The before report includes `patch-rules.ts`, so that file needs no special case.
4. Report, in the status file, each new or grown cluster with files, line ranges, tokens and one proposed fix. Check the source clusters that remain against "Left alone" and against the 53 in `2026-10-17-dedupe.cpd-baseline.md`. Give the before and after totals for source and test clusters. Remove `/tmp/cpd-before` with `git worktree remove`.

F1 does not refactor. The user decides which reported clusters to fix.

## Rework rule

A failed validation goes back to the same implementer with the failing output, at most two rounds. Then the coordinator rewrites the brief once. A task that still fails is dropped, its worktree removed and the task listed in the status file. A check that fails only with the vitest SIGSEGV is rerun once before it counts. A typecheck error in a file outside the task's list fails the task only if the error comes from the task's change.

## Risks and open decisions

Open decisions for the user:

1. `migrations.ts` holds 13 of the 53 source clusters. The default is to leave it alone. The other option is `// CPD-OFF` and `// CPD-ON` comments around the `migrations` array, if PMD honors them for TypeScript. Either way the SQL stays byte for byte.
2. S7 changes the management mock so its collection options match the server's shape. The default is yes, per the rule that mocks import the real logic. Storybook stories that show the options panel will show the new keys.
3. Whether to batch the 17 remaining wiring specs onto a shared `connectLocalDev` step later. The default is no.

Risks:

- T4 and T9 edit six files, one above the limit of about five. Each edit is a small deletion and an import. If an implementer runs out of context, the coordinator splits the task by file.
- Test helpers in `src/test/` rely on the tsconfig exclude. If ESLint's typed rules use a project that leaves out `src/test/`, lint fails on the new files. T1 and T2 fix it in the tsconfig they own, not in the ESLint config.
- S2 changes three hand-written scanners. The unit tests for statements, SQL statements, signatures and result paths are the safety net. The validator also reads the visit rules against each old loop.
- S13 changes `isPlainRecord` callers across core. A caller that relied on the old function name inside `canonical.ts` breaks at typecheck, not at runtime.
- PMD may change its tokenizer between releases. F1 scans before and after with one version, so the comparison holds, but its totals may not match the baseline file exactly.
- Worktrees each run `pnpm install` and `tsc -b`. With two workers at once this doubles disk and CPU use.
- The status file is `docs/plans/2026-10-17-dedupe.status.md`, one line per task in the form `- Id (model): status, next action`.
- Task count is 32: T0, D0, 18 source tasks, 11 test tasks and F1, in 5 phases (0 to 4). Each of the 29 implementer tasks gets its own Opus validation.
